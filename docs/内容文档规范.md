# 内容文档规范

`docs/简历内容.md` 是**纯数据文件**，只存放字段值；本文件记录它的语法、约束与项目使用规则。
改内容请改数据文件，改规则请改本文件，二者不要混在一起。

## 1. 文件定位与同步链

| 文件 | 职责 |
| --- | --- |
| `docs/简历内容.md` | 唯一内容数据源，人编辑的原稿 |
| `docs/简历模板.html` | 唯一版式原稿，栏目标题与全部样式固定在此 |
| `assets/schema.json` | 字段顺序、分组、中文标签、控件类型，由 Go 资源生成器结合模板 `data-f` 和 `docs/editor.json` 生成 |
| `assets/` | 供 `go:embed` 打包的同步副本，**不要直接编辑** |
| `docs/editor.json` | 字段标签、控件、提示及分组说明的源配置 |
| `dist/` | 桌面前端构建产物，`data.js` 提供字段、分组、初始内容及错误码 |

`scripts/build-web.mjs` 调用 Go 资源生成器，自动同步模板与内容文档、生成 schema，再生成 `dist/`。
编辑器保存时，按 `schema.json` 的顺序把内容重写成同格式的纯数据 Markdown，写到应用数据目录的
`简历内容.md`（可用 `RESUME_EDITOR_HOME` 覆盖）。因此保存前后文件格式一致，都可被再次读取编辑。

## 2. 字段语法

```
## 模块一 · 个人信息（Profile）

@@字段ID
字段值

@@另一个字段ID
字段值
```

- `@@字段ID` 开始一个字段块，其后若干非空行是字段值，空行被忽略。
- `## ` 开头的行是模块分组标题，解析器遇到会重置当前字段，不产生内容；标题文案与顺序由 schema 决定。
- 兼容规则（数据文件本身不使用）：`:: ` 开头的行与 `---` 行被忽略，代码块 ` ``` ` 整段跳过。
- 值按纯文本处理，HTML 特殊字符由渲染层转义。单字段可写多行；模板上带 `data-multiline` 的字段每行渲染为独立一行。
- 字段 ID 与模板 `data-f="字段ID"` **一一对应**，当前 **53 项**。Go 服务与资源生成器复用同一套双向校验，缺字段或多字段会报错并列出清单。
- 字段中文标签、分组、控件类型在 `docs/editor.json` 定义，生成到 `assets/schema.json`，数据文件里不重复记录。

## 3. 特殊字段

| 字段 | 规则 |
| --- | --- |
| `photo` | 默认 `【证件照】` 渲染成占位框；写成 `![证件照](./photo.jpg)` 会生成 `<img>`。图片按 29 × 37.2 mm（约 3:4）准备，放在成品 HTML 同目录用相对路径最稳。 |
| `brief` | 个人优势首行一句话概述，模板中不加粗。 |
| `proj6Desc`、`certLines` | 多行字段，每行渲染为独立一行。 |

## 4. 固定双页 A4 版式（由模板决定）

| 页面 | 内容 |
| --- | --- |
| 第 1 页 | 个人信息 + 个人优势（1 简述 + 6 条）+ 工作经历（2 条）+ 项目经验（1~4） |
| 第 2 页 | 项目经验续（5~6，不重复栏目标题）+ 教育背景（2 条）+ 资格证书 |

- A4 210 × 297 mm，`@page margin:0` + 页内 12.4 mm 安全边距；两页各自独立容器，`overflow:hidden` 加显式分页，不串页、不产生多余空白页。
- 正文 10pt / 行距 1.64；条目用 CSS Grid 列对齐、正文两端对齐。行距与对齐在原稿基础上做过专业化优化，非逐像素照搬。
- 页眉：姓名与三行信息整页水平居中；三行均为楷体小四 12pt、行距 15.7pt，无加粗与颜色差异；证件照绝对定位在内容区右上角，29 × 37.2 mm。
- 栏目标题（中英文）固定在模板中：个人优势 Self-Assessment / 工作经历 Work Experience / 项目经验 Project Experience / 教育背景 Education / 资格证书 Professional Skills；项目经验标题只在第 1 页出现一次。
- 原稿里的黑点「· ·」、回车符「↵」、红色波浪线都是 Word 编辑标记，模板一律不渲染。
- 主色 `#244664`，分隔线 `#C8D1D8`，由模板 CSS 变量统一管理。

## 5. 填写规范

1. 时间统一 `YYYY.MM-YYYY.MM`（如 `2024.03-2026.06`）；四列网格首列 31 mm，过长会挤压公司名。
2. 公司 / 学校名建议不超过 20 个汉字，保持与部门列对齐。
3. 描述建议每条 1~3 行；单页内容超长会被裁切，填写时需通过实时预览检查内容是否完整。
4. 占位文本为语义化 `【…】`，直接替换成真实内容即可。
5. 描述偏长时优先精简文字，不要改模板间距，以免破坏双页分页。

## 6. 构建与导出

```bash
node scripts/build-web.mjs          # 自动生成 schema，同步原稿并生成 dist/
npm run check                       # 语法与静态检查
npm run build                       # 构建当前桌面平台
npm run build:ubuntu                 # Linux x64 和 .deb
npm run build:macos                  # macOS 15+ Apple Silicon app
npm run build:all                    # Windows x64 + Ubuntu + macOS
```

- Windows 可执行文件名为 `resume-editor.exe`，Ubuntu 为 `resume-editor`，macOS 为 `resume-editor.app`；应用内界面文字保持中文。Mac 上构建会额外生成 `.dmg`，签名和公证配置见 README。
- **桌面应用**：打开应用，编辑字段、实时预览，点「导出 PDF」。内容保存在应用数据目录的 `简历内容.md`，成品 PDF 写入同级 `output/`；原生 WebView 打印所需的中间 HTML 也在该目录。
- 默认数据目录在 Windows 为 `%APPDATA%/resume-editor`，Ubuntu 为 `$XDG_CONFIG_HOME/resume-editor` 或 `~/.config/resume-editor`，macOS 为 `~/Library/Application Support/resume-editor`。
- PDF 导出复用系统 WebView，无需安装 Chrome / Edge / Chromium 浏览器。Windows 需要 WebView2 Runtime，macOS 15+（仅 Apple Silicon）使用系统 WKWebView，Ubuntu 的 WebKitGTK 与字体安装方式见 README。
- `RESUME_EDITOR_HOME` 可指定数据目录（便携模式 / 测试隔离）。

## 7. 编辑器交互

- 顶栏为自绘工具栏，保留各平台原生窗口按钮：左侧模块切换器与侧栏开关，右侧保存状态和「导出 PDF」按钮；工具栏按原生按钮占用空间自动避让。
- 两条中线分隔条可拖动实时调整相邻栏宽度，双击复位、方向键微调（`Shift` 加速），宽度自动记忆；最左栏收起成图标轨后仍可用模块编号切换。
- 预览缩放随预览栏宽度自适应；手动 `+/-` 后切换为手动，点缩放数值恢复自适应。
- Windows / Ubuntu 使用 `Ctrl+S` 保存、`Ctrl+B` 收起侧栏；macOS 使用 `⌘S`、`⌘B`。编辑后也会自动保存。
